# Editing the Joel and Amos print handouts

This is a **preview-only source workflow** for the quick and deep student PDFs already
listed on the Hosea and Joel and Amos, Obadiah, and Jonah lesson pages. It does not
include the later Joel in-class reader. Neither the live PDFs nor their URLs change.

- **Amos:** the recovered ReportLab authoring script lives in
  `scripts/student_handouts/amos.py`. It includes the final student-study labels
  and PDF titles, not the review-draft labels. The companion `amos_layout.py`
  controls typography, QR codes, writing lines and the footer.
- **Joel:** the original builder was not available. The two `joel-*.json` files
  are an editable reconstruction of the original ReportLab editions, not their
  original source. Edit `text`, `url`, and explicit page blocks. `top` is the block's
  upper edge in PDF points measured up from the bottom of the page; increase or
  decrease it to create space. Ordinary text wraps automatically, while explicit
  line breaks (such as bullets) stay put. A longer edit may require moving blocks
  or adding a page. The QR code is generated from its editable lesson URL.

## Build a preview

Use Python 3 (tested with 3.12), the pinned build packages, and the three
DejaVu 2.37 TrueType faces installed by the reference build environment
(`DejaVuSans.ttf`, `DejaVuSans-Bold.ttf`, and `DejaVuSerif.ttf`). On a Linux
system look for the DejaVu core fonts package; if needed give the builder
`--fonts /path/to/dejavu`. The builder checks the precise font hashes so it does
not silently substitute a different layout. On other platforms pass an explicit
font directory.

```sh
python -m pip install -r scripts/student_handouts/requirements.txt
python scripts/student_handouts/build.py --out "$(mktemp -d)"
```

The builder requires an explicit preview directory outside `handouts/` and
refuses to overwrite existing PDF outputs. Run the fidelity check below
with Git history available and Poppler (`pdftoppm`) installed. Pass
`--fonts /path/to/dejavu` to the check too if you used an alternate font path.

```sh
python tests/verify_editable_handouts.py
```

On the unchanged source this verifies stable output bytes across independent
runs and compares all nine pages against the historical untagged and current
tagged editions: exact extracted text, page and crop boxes, annotation
destinations and hit areas, and pixel-identical 150 DPI renders. Regeneration
does **not** recreate the historical binary byte for byte; metadata and tagging
differ. After editing, a difference from the current edition is normal. Inspect
the PDF against the intended edits before any release.

## Do not publish preview PDFs as-is

The preview builder does not add PDF accessibility tags. The published
downloads already contain document-heading, reading-order and link tags.
The existing tag retrofit fingerprints exact historical input PDFs and
refuses newly generated bytes, even when their visible output matches.
Do not bypass the fingerprint check, copy tags from another revision, or
replace current PDFs with untagged previews.

For a future release, use a tagged authoring path or explicitly review
and update the tag map for the new layout, then check its structure, logical
reading and tab order, heading hierarchy, and actual linked annotations.
See [student PDF structure](student-pdf-tags.md). Review the print layout,
confirm links and QR codes resolve to their intended resources, run existing
publication checks, and only then consider replacing the tagged editions.
